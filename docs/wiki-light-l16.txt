== How to enter flash mode ==
=== Using the buttons ===
# Power off the device.
# Plug it into your computer.
# Hold {{Button|Shutter}} and {{Button|Power}}.
# When the device turns on, release {{Button|Power}} but keep holding {{Button|Shutter}}.

The screen stays on the Light logo; there is no fastboot menu. Run <code>fastboot devices</code> to check that the device is in flash mode.

{{note|With the USB cable unplugged, the same buttons boot into recovery instead.}}

=== From Android ===
If USB debugging is enabled, run:

<syntaxhighlight lang="shell-session">
$ adb reboot bootloader
</syntaxhighlight>

=== Leaving flash mode ===
Run <code>fastboot reboot</code>, or hold {{Button|Power}} for about 15 seconds.

=== Windows driver ===
{{note|This is only needed on Windows.}}

In flash mode, the L16 shows up as <code>18D1:D00D</code>. The Google USB Driver doesn't include this ID, so fastboot can't see the device until you set up a driver for it.

# Enter flash mode.
# In [https://zadig.akeo.ie/ Zadig], choose ''Options → List All Devices'', select the device with USB ID <code>18D1 D00D</code>, and install ''WinUSB''.
# In Device Manager, open the device's properties and find its ''Device instance path'' on the ''Details'' tab. The serial is the part after the last backslash, e.g. <code>LFCXXXXXXXXXXXXX</code> in <code>USB\VID_18D1&PID_D00D\LFCXXXXXXXXXXXXX</code>.
# Zadig registers a different interface GUID than the one fastboot looks for. In PowerShell as administrator, add fastboot's GUID, replacing <code><serial></code> with the serial from the previous step:<syntaxhighlight lang="powershell">
$k = 'HKLM:\SYSTEM\CurrentControlSet\Enum\USB\VID_18D1&PID_D00D\<serial>\Device Parameters'
Set-ItemProperty -Path $k -Name DeviceInterfaceGUIDs -Type MultiString -Value @('{2520BF43-6602-4851-A5BE-33CAE90B7028}','{F72FE0D4-CBCB-407D-8814-9ED673D0DD6B}')
</syntaxhighlight>
# Unplug the device and plug it back in. <code>fastboot devices</code> should now list it.

== How to unlock the bootloader ==
# Enter flash mode.
# Run:<syntaxhighlight lang="shell-session">
$ fastboot oem devlock off
$ fastboot reboot
</syntaxhighlight>

No unlock code is needed, and nothing appears on screen. Your data is not erased.

== Backing up the stock partitions ==
{{note|Do this before installing postmarketOS. The L16 is no longer supported by Light, and there is no official way to get its firmware back.}}

The <code>persist</code> partition is the most important one: it holds factory calibration unique to each device. postmarketOS also loads firmware from the <code>modem</code>, <code>persist</code> and <code>system</code> partitions, so keep them intact.

=== Temporary root ===
Reading the partitions needs root. LightOS runs an old Android 6 kernel, so the [https://github.com/hyln9/VIKIROOT/releases/tag/v0.1.1 VIKIROOT] exploit gives a root shell without changing anything on the device (method from [https://xdaforums.com/t/light-l16-firmware.4403267/post-87850603 this XDA post]).

# In Android, enable developer options and USB debugging.
# Download the VIKIROOT release and extract the <code>exploit</code> file.
# Run it:<syntaxhighlight lang="shell-session">
$ adb push exploit /data/local/tmp
$ adb shell
$ cd /data/local/tmp
$ chmod +x exploit
$ ./exploit 2222
</syntaxhighlight>If it hangs at "waiting for reverse connect shell", toggle Bluetooth off and on. No prompt appears afterwards; <code>whoami</code> should print <code>root</code>.
# Copy each partition to internal storage, for example:<syntaxhighlight lang="shell-session">
# dd if=/dev/block/bootdevice/by-name/persist of=/storage/emulated/0/persist.img
</syntaxhighlight>Do the same for <code>boot</code>, <code>recovery</code>, <code>modem</code>, <code>system</code> and any other partition listed in <code>/dev/block/bootdevice/by-name/</code>, then copy the images to your computer with <code>adb pull</code>.

=== Permanent root (optional) ===
To keep root in Android, patch your own <code>boot.img</code> from the backup with the [https://github.com/topjohnwu/Magisk Magisk] app, then flash the patched image with the bootloader unlocked (on Windows this needs the driver from [[#Windows driver]]):
<syntaxhighlight lang="shell-session">
$ adb reboot bootloader
$ fastboot flash boot magisk_patched.img
$ fastboot reboot
</syntaxhighlight>
Open Magisk once more and let it finish its setup. With Magisk:
* only the first raw block device opened in each <code>su -c</code> call can be read; run one <code>dd</code> per <code>su -c</code>;
* Android's own <code>dd</code> (toybox) can't handle large offsets; use Magisk's busybox instead (<code>/sbin/.magisk/busybox/dd</code>).
